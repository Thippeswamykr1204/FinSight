# Account Aggregator readiness — not live

FinSight has a provider-neutral TypeScript boundary in `src/lib/banking/account-aggregator.ts`. No implementation is registered, no bank fetch is attempted, and the UI explicitly says bank sync is not live. Sahamati is an ecosystem alliance, not a free bank-data API. Reference: https://sahamati.org.in/ and RBI's NBFC Account Aggregator directions. An eligible regulated FIU or contracted permitted partner, licensed AA provider, approvals and test credentials are required before live operation.

The adapter models scoped, expiring consent, redirect authorization, status/revocation, cursor-based INR entries and verified raw-byte provider webhooks. It intentionally excludes bank passwords. Provider discovery must establish permitted FIU usage, consent purpose codes, retention, refresh frequency, FIP coverage, FI schemas, encryption/signature requirements, commercial pricing and India-region storage.

Before wiring an adapter: persist tenant-scoped consent and unique provider events through additive migrations; bind callback state to the authenticated user/workspace; encrypt tokens with rotatable dedicated keys; verify webhook signatures and replay IDs; recheck consent before every fetch; normalize decimal amount strings to paise; reconcile reversals and duplicate external references. Revocation must stop scheduled fetches and delete provider data according to the agreed retention policy. Prove negative signature, replay, cross-tenant, expiry and revocation cases in the provider sandbox before exposing any live connection CTA.
